# Journey acceptance matrix

| Gate | Status | Acceptance condition |
|---|---|---|
| Presenter length | GREEN design | Seven top-level scenes or fewer; rehearsed in 5–7 minutes. |
| Architecture | GREEN local | Each reveal answers one audience question and names the VM/VMI, Service, adapter, model boundary, protocol, evidence, and authority. |
| Proof | GREEN rehearsal / live pending | Typed adapters preserve healthy and unavailable evidence; a current-session VM-origin receipt on an approved cluster remains an independent gate. |
| Architecture-to-proof continuity | GREEN design | Healthy and unavailable conditions activate the same displayed topology. |
| Source state | GREEN local | `LIVE`, `REHEARSAL`, and `OFFLINE` remain visible; fixtures cannot populate a live claim. |
| Guided experience | GREEN local | The separate 60–75 minute guide follows the same correlation ID and evidence identifiers. |
| Hands-on lab | AMBER | Contract and content are implemented locally; GREEN requires one clean development-cluster run. |
| Handoff | GREEN design | The presentation closes, then offers one 60–75 minute 101 lab handoff. |
| Level | GREEN | 101 is trace/explain; 201 remains a separate learner-build journey. |
| Packaging | GREEN local / publication pending | Digest-pinned `linux/amd64` OCI candidates and clean Trivy scans exist; approved-registry publication, signing, and pull evidence remain external gates. |
| Launchpad | RED until independent review | Factory evidence never grants catalog certification or promotion authority. |
