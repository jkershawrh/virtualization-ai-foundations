= Verify the runtime
:navtitle: 1. Verify

== Show

Use the *OpenShift Console* tab before the terminal commands:

. Open *Virtualization → VirtualMachines* and select `{vm_name}`.
. Open its *VirtualMachineInstances* details and note the phase, node, and guest IP.
. Open *Workloads → Deployments* and inspect `ai-analysis-adapter` and
  `virtualization-ai-presentation` in `{namespace}`.

The Console is the operator view of the same namespace-scoped objects proved
below. Stop if the tab is missing, shows another namespace, or cannot authenticate.

== Check this seat's virtualization runtime

Launchpad verifies the cluster-wide OpenShift Virtualization operator before
placing the lab. Your participant identity is limited to this seat's namespace;
it cannot inspect the platform-management namespace. Prove the runtime available
to you by waiting for this seat's VirtualMachineInstance to become ready.

[source,bash,role="execute",subs=attributes+]
----
oc wait -n {namespace} --for=condition=Ready vmi/{vm_name} --timeout=120s
----

Continue only when the command reports `condition met`. This proves your VM
runtime is ready, not that you have cluster-wide operator permissions.

== Identify the VM and VMI

[source,bash,role="execute",subs=attributes+]
----
oc get vm,vmi -n {namespace} -l app.kubernetes.io/part-of=virtualization-ai-101 -o wide
----

Record the VirtualMachine name, VirtualMachineInstance phase, node, and guest IP.
The VM and VMI are related but different runtime objects; the running VMI is the
current guest execution.

== Prepare this seat's VM credential

Launchpad generates a different SSH keypair for every seat. The public half is
installed in this VM by cloud-init. Extract only this seat's private half into
the terminal; do not print it or copy it outside the lab.

[source,bash,role="execute",subs=attributes+]
----
install -d -m 700 "$(dirname {ssh_key_path})"
oc get secret virtualization-ai-model-runtime -n {namespace} \
  -o jsonpath='{.data.VM_SSH_PRIVATE_KEY}' | base64 -d > {ssh_key_path}
chmod 600 {ssh_key_path}
test -s {ssh_key_path} && echo "seat VM credential ready"
----

This credential is namespace-scoped, expires with the seat, and is removed by
reclamation. It exists so the request in the next stages really originates in
the VM rather than in the browser, presentation, or certification runner.

== Check the adapter source state

[source,bash,role="execute",subs=attributes+]
----
curl --connect-timeout 5 --max-time 30 -fsS http://{adapter_service}:8080/healthz | jq .
----

`mode: live` is required for a live AI claim. `rehearsal` or `offline` remains
useful for practicing the journey but cannot satisfy the proof gate.
